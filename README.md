# swift-postgresql

Use this package when your queries are written with swift-sql and run against PostgreSQL, or when you need PostgreSQL features the standard SQL layer doesn't have: arrays, JSONB, full-text search, window functions, triggers and LISTEN/NOTIFY. Depend on `PostgreSQL SQL` to build statements without a database, and on `PostgreSQL` with its `PostgresNIO` trait on to run them: start from `PostgreSQL.Configuration` and `PostgreSQL.Database`. For tests that need a real server, use `PostgreSQL.TestDatabase.Scope` from `PostgreSQL Test Support`. If your database is SQLite, use swift-sqlite.

## Laws

- Bound values are numbered `$1`, `$2` and so on. When a value is inlined instead, an instant becomes a UTC `TIMESTAMPTZ` literal, bytes become a hex `BYTEA` literal, and an array becomes `ARRAY[...]` cast to its element type.
- `PostgreSQL SQL` renders and runs nothing, and names no engine. `PostgreSQL` re-exports it; its database exists only with the `PostgresNIO` trait on, which is off by default. No public symbol of either names the engine underneath, so replacing the engine changes nothing a consumer sees; `The public API` test checks this with every trait on.
- `PostgreSQL.Database(configuration:)` connects on first use and keeps at most `poolSize` connections. Each body is synchronous and runs on one of the database's own `poolSize` threads, holding one connection while it runs. A call waits at most `acquireTimeout` for a free connection, then throws a `.timeout` error. `close()` ends the connections and threads, as does the last copy of the database going away; a call after `close()` throws `.closed`.
- `PostgreSQL.Database.read(_:)` runs its body in a read-only transaction and `PostgreSQL.Database.write(_:)` in a read-write one. Both commit when the body returns and roll back when it throws, or when the calling task was cancelled while the body ran, which then throws `.cancelled`. If the rollback itself fails, the connection is closed and the error says so. `PostgreSQL.Database.withRollback(_:)` always rolls back, and `PostgreSQL.Database.writeWithoutTransaction(_:)` opens no transaction.
- Errors are `PostgreSQL.Error`: a `kind` (`server`, `connect`, `tls`, `authentication`, `timeout`, `closed`, `cancelled`, `value`), the SQLSTATE `code` when the server gave one, its message, detail and statement. A body that throws anything gets its own errors back unchanged and the database's as `PostgreSQL.Error`, including a server error a connection reported to the body, so a unique violation arrives with code `23505`. The `ISO_9075.Error` forms carry the same text in `.execution`.
- A connection that can't be opened fails the waiting call at once with the server's reason: a wrong password is `.authentication`, an unknown database `.connect` with `3D000`, nothing listening `.connect`. The pool keeps trying in the background, so a later call succeeds once the server answers. A connection that dies during a call fails that call with `.closed`; the next call gets a new connection.
- `PostgreSQL.Connection.withSavepoint(_:_:)` releases its savepoint when the body returns. When the body throws it rolls back to the savepoint and rethrows, and the outer transaction carries on.
- An empty statement is not sent to the server: executing it affects 0 rows and fetching it returns nothing.
- Instants are bound as `TIMESTAMPTZ` with microsecond precision, whatever the session's time zone. Finer digits are dropped toward the earlier microsecond. A `date` column reads as midnight UTC.
- An array binds as one value only if every element has the array's kind and none is null. Decimal and JSON arrays can't be bound. Arrays decode from the one-dimensional text form only, and a null element fails for a non-optional element type.
- A decimal binds only if its text is a number, `NaN` or `Infinity`.
- `PostgreSQL.JSONB<Value>` encodes with sorted keys and dates as ISO 8601 with fractional seconds. It decodes PostgreSQL's own timestamps, with or without a zone offset.
- `PostgreSQL.Cursor<Element>` declares a forward-only cursor and fetches `batch` rows at a time. A cursor lives only inside a transaction, so use it within `read` or `write`.
- `fetchOne` adds `LIMIT 1` when the statement selects whole rows of a table. A statement that selects chosen columns is fetched in full and its first row kept.
- `PostgreSQL.Configuration(url:)` reads `postgres://` and `postgresql://` URLs. User, password and database are percent-decoded, the port defaults to 5432 and the database to the user. `sslmode` is `disable` (the default), `require` or `verify-full`, and `sslrootcert` names a PEM file of extra roots, or `system`. Other parameters are ignored. A malformed URL throws `invalidURL` naming the part that is wrong.
- `PostgreSQL.Configuration(environment:)` reads `DATABASE_URL` when it is set. Otherwise it reads each `DATABASE_` variable before its `POSTGRES_` counterpart, and TLS from `DATABASE_SSLMODE` and `DATABASE_SSLROOTCERT`. The password may be missing. The pool closes connections idle for 60 seconds and pings every 30 seconds to keep them alive.
- TLS `.disabled` sends everything in the clear. `.required` encrypts but checks nothing about the server. `.verified` checks the certificate chain against the system's roots plus any `rootCertificates`, and the certificate's name against `host`. Because an address has no name to check, `.verified` with an IP address for a host is refused when the database is made.
- `PostgreSQL.Notification.Channel.setUp(on:_:timing:includingOld:)` installs a trigger that sends each insert, update and delete after it happens, with the new row and, if asked, the old one. An insert has no old row and a delete no new row. Rows travel through `row_to_json`, so a notification decodes the same way whether a trigger or `notify(_:)` sent it.
- `PostgreSQL.Database.listen(on:consume:)` holds one connection for as long as `consume` runs, and stops listening when it returns.
- `PostgreSQL.TextSearch.query(_:configuration:syntax:)` parses with the web search syntax unless told otherwise. A generated search vector treats a null source column as empty text.
- A trigger function's body is dollar-quoted under `$function$`, or under the first of `$function_1$`, `$function_2$` and so on that the body doesn't contain.
- `PostgreSQL.TestDatabase.Scope` creates a database with a random name for each suite, runs the set-up statements, and drops it with `FORCE` afterwards, also when the suite fails. If no server answers at the default address and `POSTGRES_HOST` is unset, the suite is cancelled rather than failed; with `POSTGRES_HOST` set it fails. `PostgreSQL.Configuration.test` defaults to `localhost`, port 5432, the current user (`USER`), database `swift_postgresql_test`, without TLS; the scope administers from the `postgres` database when that one doesn't exist. Each `POSTGRES_` variable overrides its part, and `POSTGRES_SSLMODE` and `POSTGRES_SSLROOTCERT` set TLS.
